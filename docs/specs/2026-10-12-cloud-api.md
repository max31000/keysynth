# keysynth cloud — REST contract, storage layout, file formats

Status: contract (WP0). Design: `2026-10-12-cloud.md` (§11 overrides earlier sections). Engine ⇄ UI messages:
`docs/PROTOCOL.md` *Cloud & samples*. Platform conventions: `docs/research/MVV42_PLATFORM.md`.

## 1. General

- Public URLs `https://mvv42.ru/keysynth/api/...`; nginx maps `/keysynth/api/` → app `/api/` (app routes start at `/api/`). The engine's configured base is the service root `https://mvv42.ru/keysynth` and it appends `/api/...`. Health:
  `GET /health` (public `/keysynth/health`), anonymous, `200 {"status":"ok"}`.
- JSON: UTF-8, camelCase, enums as strings, timestamps ISO 8601 UTC with `Z` (ms precision optional on input).
- Errors: `{"error":"<code>"}` (+ optional extra fields listed per endpoint). Common codes:

| status | `error` | when |
|---|---|---|
| 400 | `invalid_request` | malformed JSON / missing or invalid field |
| 400 | `invalid_slug` | slug fails §5.1 |
| 400 | `invalid_patch` | patch is not a JSON object with numeric `format` |
| 400 | `invalid_song` | song is not a JSON object with numeric `format` (§3.3a) |
| 401 | `unauthorized` | no / invalid cookie and no bearer |
| 401 | `token_invalid` | bearer unknown, malformed or revoked |
| 401 | `token_expired` | bearer past `expiresAt` |
| 401 | `reauth_required` | bearer valid but user's `last_app_ok_at` > 30 days old (§2.3) |
| 403 | `forbidden` | authenticated but no `keysynth` grant, or wrong scheme for the endpoint |
| 403 | `origin_not_allowed` | SDK CSRF check (cookie + unsafe method + foreign Origin) |
| 404 | `not_found` | unknown resource / file not in the index |
| 409 | `too_many_devices` | > 10 devices per user |
| 409 | `too_many_presets` | > 1000 presets per user |
| 409 | `too_many_songs` | > 1000 songs per user |
| 412 | `revision_mismatch` | `If-Match` / `If-None-Match` precondition failed |
| 413 | `payload_too_large` | body over the limit (§7) |
| 428 | `precondition_required` | write without `If-Match` / `If-None-Match` |
| 429 | `rate_limited` | §7; `Retry-After` header (seconds) |
| 500 | `internal` | anything else |

- 401 responses carry `WWW-Authenticate: Bearer error="<code>"` for bearer requests.

## 2. Auth

### 2.1 Schemes and policies
- `mvv42` (cookie): `AddMvv42Auth("keysynth", …)` from `Mvv42Auth.cs` (copied, unchanged). Policy `mvv42:app`.
- `device` (bearer): `Authorization: Bearer ksd_…`, custom `DeviceTokenHandler` (§2.2).
- Policies: `Cookie` = `mvv42:app`; `Device` = scheme `device`; `AnyUser` = `Cookie` OR `Device`.
- Local user: provisioned/updated on every successful cookie request by `tg` (`users.telegram_id`), `name` from the
  token. `accountId` on the wire = `users.id` as a **string**; `accountName` = `users.name`.

### 2.2 Device tokens
- Format: `ksd_` + base64url (no padding) of 32 random bytes (CSPRNG) → 47 chars total. Regex
  `^ksd_[A-Za-z0-9_-]{43}$`.
- Stored only as `SHA-256(token string, UTF-8)` (32 bytes) in `devices.token_hash`; lookup by hash, compared in
  constant time.
- Lifetime 180 days from mint (`expires_at`). The page re-mints (`POST /api/devices`, same `deviceId`) when less
  than 30 days remain or whenever the engine reports `linked: false` while the user is logged in; re-mint replaces
  the hash (the old token stops working at once).
- `deviceId`: UUID v4 string (lowercase, with dashes) generated by the engine once per PC (`cloud.json`).
- Each successful device request sets `devices.last_seen_at` (at most once per minute).

### 2.3 `last_app_ok_at` rule
- Every cookie request that passes `mvv42:app` sets `users.last_app_ok_at = now` (DB write at most once per hour).
- The device handler rejects (401 `reauth_required`) when `now - users.last_app_ok_at > 30 days`. Effect: a revoked
  grant or blocked user (cookie requests stop passing) loses device access within 30 days; opening the page while
  still granted refreshes it.
- Order of device checks: format → hash lookup (`token_invalid`) → `expires_at` (`token_expired`) →
  `last_app_ok_at` (`reauth_required`) → success (principal: `userId`, `deviceId`).

### 2.4 CSRF / Origin
Cookie writes are covered by the SDK Origin filter (`AllowedOrigins = ["https://mvv42.ru"]`). Bearer requests carry
no ambient credential. No CORS in production (same origin); dev CORS for `http://localhost:5173` only when
`ASPNETCORE_ENVIRONMENT=Development`.

### 3.0 Relay
`GET /api/relay` is the only WebSocket endpoint. Auth runs before the upgrade with the same schemes, but per role:
host = device bearer only, controller = granted cookie only plus an exact allowed `Origin` (the SDK Origin filter
covers unsafe methods only; an upgrade is a GET). Deleting a device (`DELETE /api/devices/{id}`, `/me`) closes its
relay socket at once. Envelope, routing, limits and close codes: docs/PROTOCOL.md *Relay*. Options: configuration
section `Relay` (`server/src/Keysynth.Api/Relay/RelayOptions.cs`; defaults are the contract).

### 3.1 Devices
```jsonc
// POST /api/devices  request
{ "deviceId": "3f0c7e9a-5b1d-4c2e-9a77-0e5d2c1b8f40", "name": "MAX-PC" }   // name 1..100 chars, trimmed
// DeviceMinted
{ "deviceId": "3f0c7e9a-…", "token": "ksd_…", "expiresAt": "2027-04-10T12:00:00Z",
  "accountId": "17", "accountName": "Max" }
// Device (GET /api/devices items)
{ "deviceId": "3f0c7e9a-…", "name": "MAX-PC", "createdAt": "…", "lastSeenAt": "…" /* or null */, "expiresAt": "…" }
// DeviceMe
{ "deviceId": "3f0c7e9a-…", "name": "MAX-PC", "accountId": "17", "accountName": "Max", "expiresAt": "…" }
```
- The token is returned only by `POST`, never again. Rows are per (user, deviceId): several accounts may hold a row
  for the same PC; the engine keeps one token.
- `DELETE …/{deviceId}` / `…/me` delete the row (no soft delete).

### 3.2 Samples
- Manifest response = the server `index.json` bytes verbatim (§4.2), `Content-Type: application/json`,
  `ETag: "<first 16 hex of SHA-256(index.json)>"`, `Cache-Control: no-cache`. The API reloads `index.json` when its
  mtime changes. Missing/invalid index → 503 `index_unavailable`.
- Files: `{lib}` + `{*path}` (URL-decoded) must equal a `files[].path` of library `lib` in the loaded index
  (exact, case-sensitive) → else 404. Success: status 200, empty body, headers
  `X-Accel-Redirect: /keysynth/_files/<lib>/<path>` with every segment percent-encoded (RFC 3986 unreserved kept,
  `/` between segments kept; spaces, Cyrillic, `#`, `?`, `%`, `+` encoded), `Cache-Control: private, no-store`.
  nginx then serves the file from `/var/lib/keysynth/samples/` with `Range`/`If-Range`/`ETag`/`Last-Modified`
  (nginx defaults), so the engine sees 200/206/416 and nginx's `ETag`.
- Engine resume: keep the `ETag` of the first response with the `.part`; resume with `Range: bytes=<n>-` +
  `If-Range: <etag>`; a 200 instead of 206 means the file changed → restart from 0. Final check = `sha256` from the
  manifest.
- Client URL encoding: the engine percent-encodes each path segment the same way when requesting.

### 3.3 Presets
Only the engine writes (UI edits go through the engine). Resource shapes:
```jsonc
// PresetMeta
{ "slug": "warm-rhodes", "revision": 4, "updatedAt": "2026-10-12T14:03:00.123Z", "deleted": false }
// Preset = PresetMeta + patch (null when deleted)
{ "slug": "warm-rhodes", "revision": 4, "updatedAt": "…", "deleted": false, "patch": { "format": 1, "meta": {…}, … } }
// PUT body
{ "patch": { "format": 1, … } }
```
- `ETag: "<revision>"` (e.g. `"4"`, strong). `revision` starts at 1 and +1 on every PUT/DELETE; `updatedAt` = server
  time of that write.
- `PUT` create: `If-None-Match: *` → 201; if a row exists (live or tombstone) → 412. Update/revive: `If-Match:
  "<rev>"` equal to the current revision → 200; else 412. Neither header → 428.
- `DELETE` with matching `If-Match` → tombstone (`deleted: true`, `patch` NULL, revision +1). Unknown slug → 404.
- 412 body: `{"error":"revision_mismatch","current": PresetMeta}`.
- `GET /api/presets` returns all rows incl. tombstones (≤ 1000, ordered by slug); no paging. Tombstones are kept
  forever.
- The patch is stored as received (bytes of the `patch` value re-serialised by System.Text.Json, not normalised);
  the server validates only: JSON object, numeric `format`, size ≤ 256 KB.

### 3.3a Songs
Setlists (docs/PRESETS.md *Songs*), same scheme as presets — only the names differ:
```jsonc
// SongMeta
{ "slug": "riders-on-the-storm", "revision": 2, "updatedAt": "2026-10-13T10:00:00.000Z", "deleted": false }
// Song = SongMeta + song (null when deleted)
{ "slug": "riders-on-the-storm", "revision": 2, "updatedAt": "…", "deleted": false, "song": { "format": 1, "title": "…", … } }
// PUT body
{ "song": { "format": 1, … } }
```
- Revisions, `ETag`, `If-Match` / `If-None-Match: *`, 412 body (`{"error":"revision_mismatch","current": SongMeta}`),
  tombstones, ordering and the "stored as received" rule are exactly §3.3.
- Validation: `song` is a JSON object with a numeric `format`, ≤ 256 KB serialised → else 400 `invalid_song` /
  413 `payload_too_large`. ≤ 1000 songs per user incl. tombstones → 409 `too_many_songs`.
- Writes share the preset write rate limit (one bucket, 120 / minute / user).
- Table `songs` (migration `002_songs.sql`): same columns as `presets` with `song MEDIUMTEXT NULL` (NULL iff deleted).

### 3.4 Engine sync algorithm (normative for WP B)
Per-profile `sync.json` (§6.4) keeps for each slug `{ baseRevision, hash }` (hash = SHA-256 of the local file
bytes at last sync). One pass:
1. `GET /api/presets`.
2. For each slug in server ∪ local (conflict files `*.conflict-*.json` excluded):
   - local unchanged (hash == base hash) and server revision > base → download (`GET`), or delete local if tombstone.
   - local changed, server revision == base → `PUT If-Match: "<base>"` (or `DELETE` if the local file was deleted).
   - local new (no base entry), server absent → `PUT If-None-Match: *`.
   - local new or changed and server changed (revision > base, or 412 on push):
     - server tombstone → **edit wins**: `PUT If-Match: "<server revision>"`.
     - otherwise **server wins**: local file renamed to `<slug>.conflict-<yyyyMMddTHHmmssZ>.json`, server version
       downloaded to `<slug>.json`.
   - local deleted, server changed → download (server edit wins over local delete).
   - server absent, local unchanged with a base entry → server row was never there (purged): re-upload.
3. Update `sync.json` after each successful step (crash-safe: write temp + rename).
Initial link = the same pass with an empty `sync.json` (uploads local-only, downloads server-only; same-slug both
sides → server wins + conflict file unless bytes are identical).
Songs run the same pass right after presets: `userdata/songs/` ⇄ `/api/songs` (body key `song`), base entries in
`sync.json` → `songs`; an abort (offline / unauthorized / rate limited) in the preset part skips the song part.

## 4. Samples catalogue

### 4.1 Producer
`scripts/build_sample_index.py` reads `assets/samples.json` + the extracted files under `assets/samples/<lib>/`,
parses every listed `sfz` with the real SFZ rules (`#include`, `#define`, `default_path`, `sample=` incl. paths
with spaces) and writes `index.json`. Paths are case-corrected to the real filesystem names, `/`-separated, NFC,
relative to the library dir. It fails (non-zero exit) on any missing file or invalid path. Output uploaded to
`/var/lib/keysynth/samples/index.json` next to the libraries (`/var/lib/keysynth/samples/<lib>/…`).

Path validation (builder, API and engine — identical rules): non-empty segments, no `.`/`..`, no leading `/`, no `\`,
`:`, control chars (< 0x20, 0x7F), no segment ending in `.` or space, no Windows reserved names (`CON PRN AUX NUL
COM1-9 LPT1-9`, with any extension), total ≤ 240 chars. Engine additionally canonicalises and checks the result is
under the cache root.

### 4.2 `index.json` (= manifest)
```jsonc
{
  "format": 1,
  "generatedAt": "2026-10-12T12:00:00Z",
  "groups": [ { "id": "piano", "name": "Piano" }, { "id": "epiano", "name": "Electric piano" } ],
  "libraries": [
    {
      "id": "salamander",                        // [a-z0-9][a-z0-9-]*, = assets/samples/<id>
      "name": "Salamander Grand Piano V3+20200602 (SFZ+FLAC)",
      "group": "piano",                          // = samples.json "category"; must be in groups[]
      "licence": "CC-BY-3.0", "author": "Alexander Holm", "attribution": "…",
      "bytes": 1960000000,                       // sum of files[].bytes
      "files": [ { "path": "SalamanderGrandPiano-SFZ+FLAC-V3+20200602/48khz24bit/A0v1.flac",
                   "bytes": 1234567, "sha256": "<64 lowercase hex>" } ],
      "entries": [
        { "id": "salamander/SalamanderGrandPiano-SFZ+FLAC-V3+20200602/SalamanderGrandPiano-V3+20200602.sfz",
          "sfz": "SalamanderGrandPiano-SFZ+FLAC-V3+20200602/SalamanderGrandPiano-V3+20200602.sfz",
          "name": "SalamanderGrandPiano-V3+20200602",   // file stem unless samples.json gives a name
          "files": [0, 1, 2],                           // indices into files[]: the .sfz, includes, samples
          "bytes": 1960000000 }                         // sum over its files
      ]
    }
  ]
}
```
Group order, library order (samples.json order) and entry order (`sfz` list order) are display order. Entry `id` =
`<library id>/<sfz>` (PROTOCOL.md).

### 4.3 Engine `samples/cache.json`
```jsonc
{
  "format": 1,
  "manifestEtag": "\"9c1f0a2b3c4d5e6f\"",          // of samples/manifest.json (cached manifest copy)
  "manifestFetchedAt": "2026-10-12T14:00:00Z",
  "files": {                                      // complete, verified files only; key = "<lib>/<path>"
    "salamander/SalamanderGrandPiano-SFZ+FLAC-V3+20200602/48khz24bit/A0v1.flac":
      { "bytes": 1234567, "sha256": "<hex>", "verifiedAt": "2026-10-12T14:01:00Z" }
  },
  "partial": {                                    // resumable downloads (<cache>/<lib>/<path>.part)
    "salamander/…/A1v1.flac": { "bytesDone": 524288, "etag": "\"66f0-12d687\"" }
  }
}
```
- Written only by the download worker / delete handler (temp + rename). On start the engine drops `files` entries
  whose file is missing or has another size, and `partial` entries without a `.part`.
- A file listed in a new manifest with a different `sha256` than `files[...]` counts as missing (re-download).
- Entry status = from `files` vs the entry's manifest file list (PROTOCOL.md `samples_list_ok`).

## 5. Data model

### 5.1 Slugs
`^[a-z0-9]+(-[a-z0-9]+)*$`, 1..64 chars (= `PresetStore::slugify` output). Conflict files never reach the server.

### 5.2 MySQL DDL (database `keysynth`, migrations `server/src/Keysynth.Infrastructure/Migrations/NNN_*.sql`)
```sql
CREATE TABLE schema_migrations (
  version     INT          NOT NULL PRIMARY KEY,
  applied_at  DATETIME(3)  NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE users (
  id              BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  telegram_id     BIGINT       NOT NULL,
  auth_user_id    VARCHAR(64)  NOT NULL,             -- mvv42 `sub`
  name            VARCHAR(255) NOT NULL DEFAULT '',
  created_at      DATETIME(3)  NOT NULL,
  last_app_ok_at  DATETIME(3)  NOT NULL,
  UNIQUE KEY ux_users_telegram (telegram_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE devices (
  id            BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  user_id       BIGINT       NOT NULL,
  device_id     CHAR(36)     NOT NULL,
  name          VARCHAR(100) NOT NULL,
  token_hash    BINARY(32)   NOT NULL,
  created_at    DATETIME(3)  NOT NULL,
  expires_at    DATETIME(3)  NOT NULL,
  last_seen_at  DATETIME(3)  NULL,
  UNIQUE KEY ux_devices_user_device (user_id, device_id),
  UNIQUE KEY ux_devices_token (token_hash),
  CONSTRAINT fk_devices_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE presets (
  user_id     BIGINT        NOT NULL,
  slug        VARCHAR(64)   CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  revision    INT UNSIGNED  NOT NULL,
  updated_at  DATETIME(3)   NOT NULL,
  deleted     TINYINT(1)    NOT NULL DEFAULT 0,
  patch       MEDIUMTEXT    NULL,                    -- NULL iff deleted
  PRIMARY KEY (user_id, slug),
  CONSTRAINT fk_presets_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```
Writes to `presets` use a conditional `UPDATE … WHERE user_id=? AND slug=? AND revision=?` (affected rows = 0 →
412) / `INSERT` (duplicate key → 412).

## 6. Local storage (engine)

### 6.1 AppPaths
Mode: **installed** iff `installed.flag` exists next to the exe; else **dev**. Override for tests: `KS_DATA_DIR`
(replaces the data root in both modes). API base: compiled service root `https://mvv42.ru/keysynth`; `--cloud-api <url>` /
`KS_CLOUD_API` override (dev builds only).

| item | installed | dev (repo checkout) |
|---|---|---|
| app (read-only: exe, `faust.dll`, `share/faust`, `presets/factory`, `presets/patterns`, `ui/dist`) | `%LOCALAPPDATA%\Programs\keysynth\` | repo root |
| data root `D` | `%LOCALAPPDATA%\keysynth\` | `<repo>\userdata\` |
| settings | `D\settings.json` | `<repo>\userdata\settings.json` (as today) |
| cloud state | `D\cloud.json` | `<repo>\userdata\cloud.json` |
| logs | `D\logs\` | `<repo>\userdata\logs\` (as today) |
| profile root | `D\userdata\` (local profile) | `<repo>\userdata\` (as today) |
| linked profiles | `D\userdata\accounts\<accountId>\` | `<repo>\userdata\accounts\<accountId>\` |
| recordings | `D\userdata\recordings\` | `<repo>\userdata\recordings\` |
| user plugins | `D\plugins\` | `<repo>\plugins\` |
| plugin build / Faust cache | `D\faust-cache\` | `<repo>\plugins\.build\` (as today) |
| sample cache | `D\samples\` | `<repo>\userdata\samples\` |

Profile dir layout (local or account): `presets\<slug>.json`, `patterns\<slug>.json`, `songs\<slug>.json`,
`sync.json` (accounts only). Factory songs: app dir `presets\songs\`.
Logical paths (PROTOCOL.md): `userdata/…` → active profile dir, `presets/factory|patterns/…` → app dir,
`assets/samples/<lib>/<path>` → first hit of repo `assets/samples/`, `$KS_ASSETS_DIR/samples/`, sample cache
`<lib>\<path>`. All of these roots are on the WS path allow-list (ARCHITECTURE §11).

Sample cache dir: `<lib>\<path>` (verified files), `<lib>\<path>.part` (in progress), `cache.json`, `manifest.json`
(last fetched manifest, verbatim).

### 6.2 `cloud.json`
```jsonc
{ "format": 1,
  "deviceId": "3f0c7e9a-5b1d-4c2e-9a77-0e5d2c1b8f40",    // created on first start, never changes
  "deviceName": "MAX-PC",                                 // %COMPUTERNAME% at creation
  "link": null }                                          // or:
// "link": { "accountId": "17", "accountName": "Max", "expiresAt": "2027-04-10T12:00:00Z",
//           "token": "<base64 of CryptProtectData(token UTF-8, CurrentUser, entropy = \"keysynth-cloud-v1\")>" }
```
Only `link.token` is DPAPI-protected; the rest is plain so the engine can report `deviceId` without decrypting.
Decrypt failure (other Windows user/profile copy) → treat as unlinked, keep `deviceId`.

### 6.3 `settings.json`
Unchanged keys (`audio`, …); no cloud data in it.

### 6.4 `sync.json` (per account profile)
```jsonc
{ "format": 1, "lastSyncAt": "2026-10-12T14:03:00Z",
  "presets": { "warm-rhodes": { "baseRevision": 4, "hash": "<sha256 hex of local file bytes at last sync>" } },
  "songs":   { "riders-on-the-storm": { "baseRevision": 2, "hash": "<sha256 hex>" } } }
```
Each collection rewrites only its own key (read-modify-write under the profile mutex).

## 7. Limits

| item | limit |
|---|---|
| request body (nginx `client_max_body_size` on `/keysynth/api/`) | 1 MB |
| preset `patch` | 256 KB serialised; else 413 |
| presets per user (incl. tombstones) | 1000; creating more → 409 `too_many_presets` |
| song `song` | 256 KB serialised; else 413 |
| songs per user (incl. tombstones) | 1000; creating more → 409 `too_many_songs` |
| devices per user | 10; else 409 `too_many_devices` |
| device name | 1..100 chars |
| `POST /api/devices` | 10 / hour / user |
| preset writes (PUT/DELETE) | 120 / minute / user |
| manifest | 60 / minute / user |
| `/api/samples/files` | no API limit; nginx `_files`: `limit_conn` 4 per IP, `limit_rate` 8m per connection |
| engine | 2 parallel file downloads, manifest revalidation ≤ 1 / minute except explicit `samples_list` |
| `/api/relay` | per user 4 hosts / 8 controllers; frames host 1 MB, controller 128 KB; 300 / 100 msg/s; details docs/PROTOCOL.md *Relay* |
