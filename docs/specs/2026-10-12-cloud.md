# keysynth on mvv42.ru — semi-cloud design (Windows first)

Status: draft rev 1 (to be reviewed). Platform facts: `docs/research/MVV42_PLATFORM.md` (source of truth for
platform conventions; not repeated here).

## 1. Goal (owner UX, in order)

1. Open `https://mvv42.ru/keysynth/` (standalone or inside the shell `#/keysynth`), logged in via the platform.
2. If no local engine is detected: one button **«Скачать для Windows»** = direct link
   `https://github.com/max31000/keysynth/releases/latest/download/keysynth-setup.exe`, plus 3-line install hint.
3. Run the installer: Start-menu entry (pinnable), optional desktop icon, optional autostart, tray icon.
4. Engine starts → page connects to it automatically → engine is linked to the account automatically (no codes)
   → presets/plugins sync → pick a preset → its samples download if missing → play.
5. Works offline afterwards (engine serves its bundled UI at `http://127.0.0.1:7340` as fallback).

Non-goals: sound over the network (latency), browser-only engine, macOS (separate task, later), multi-user
features beyond what the platform gives.

## 2. Topology

```
 mvv42.ru (VDS)                                                  Owner PC (Windows)
 nginx ─ /keysynth/            SPA (ui/, Vite base /keysynth/)   browser tab ──ws://127.0.0.1:7341──┐
       ─ /keysynth/api/  ───►  keysynth-api (.NET 8, :5020)        (page from mvv42.ru)               │
       ─ /keysynth/health      ├ MySQL db `keysynth` (cashpulse-mysql)                               ▼
       ─ internal /keysynth/_files/ ◄─ X-Accel-Redirect        keysynth-engine.exe (tray app)
            alias /var/lib/keysynth/samples                     ├ audio/MIDI (unchanged)
 GitHub Releases: keysynth-setup.exe (public repo)              ├ CloudClient: HTTPS to /keysynth/api with
                                                                │   device token (Authorization: Bearer)
                                                                ├ SampleCache %LOCALAPPDATA%\keysynth\samples
                                                                └ user data %LOCALAPPDATA%\keysynth\userdata
```

## 3. Identity & linking

- Web page: platform auth (`@mvv42/kit/platform`, cookies). App registered `access='invite'`, `anonymous=1` so the UI
  still loads signed-out (local-only use: factory presets, cached samples).
- **Device token.** Engine cannot use browser cookies. Flow, fully automatic:
  1. Page connects to the local engine (WS). Engine `hello` reply includes `cloud: { linked, accountName?, deviceId }`.
  2. If not linked (or linked to another account) and the user is logged in, the page calls
     `POST /keysynth/api/devices { deviceId, name }` (cookie auth) → `{ token }` (random 256-bit, stored hashed
     SHA-256 in DB, bound to user + deviceId, no expiry, revocable).
  3. Page sends `cloud_link { baseUrl: "https://mvv42.ru/keysynth/api", token }` over WS → engine stores it in
     `%LOCALAPPDATA%\keysynth\cloud.json` protected with Windows DPAPI (CurrentUser) → replies `cloud_status`.
  4. Engine then calls the API with `Authorization: Bearer <token>`. `GET /api/devices/me` validates.
  - `cloud_unlink` (UI button) deletes local token and calls `DELETE /api/devices/{id}`.
- Engine WS Origin allow-list gains `https://mvv42.ru`. Accepting a token from that origin is safe because only
  pages served from mvv42.ru (same-origin with the platform) can send it.
- Chrome Local Network Access: public page → loopback triggers a one-time permission prompt; inside the shell
  iframe it also needs `allow="local-network-access"` on the iframe → shell gets a per-service `allow` field in
  `registry.json`. Fallback if blocked: a link «Открыть отдельно» (standalone page) and the local UI at :7340.

## 4. Backend `keysynth-api` (repo `server/`)

.NET 8 minimal API, platform layout `server/src/Keysynth.Api|Core|Infrastructure`, xUnit tests, Dapper +
MySqlConnector, own SQL migrations on startup, `Mvv42Auth.cs` copied from mvv42-auth SDK. Two auth schemes:
platform cookie (`mvv42` policy) for browser calls, `device` bearer scheme for engine calls; most endpoints accept
either (`AnyUser` policy). Local user provisioned by `tg`.

| Endpoint | Auth | Purpose |
|---|---|---|
| `GET /health` | anon | deploy health |
| `POST /api/devices` / `GET /api/devices` / `DELETE /api/devices/{id}` | cookie | link / list / revoke engines |
| `GET /api/devices/me` | device | token check, account name |
| `GET /api/samples/manifest` | any | library catalogue (§5) with `etag` |
| `GET /api/samples/files/{lib}/{*path}` | any | authorise → `X-Accel-Redirect: /keysynth/_files/{lib}/{path}` (nginx serves, Range/resume) |
| `GET/PUT/DELETE /api/presets[/{slug}]` | any | user presets (JSON ≤ 256 KB), `updatedAt`, `If-Match` etag |
| `GET/PUT/DELETE /api/plugins[/{name}]` | any | Faust/C++ plugin sources (text ≤ 512 KB) + plugin.json |
| `GET /api/releases/latest` | anon | cached GitHub latest release {version, url, notes} for UI banner |

Rate limits: modest per-user limits on writes. Max body 1 MB (nginx `client_max_body_size 1m`).
Container: `keysynth-api`, port 5020, network `cashpulse-network`, volume `/var/lib/keysynth:/data:ro`
(api only needs to stat files for the manifest; nginx serves them).

## 5. Samples

- Server store: `/var/lib/keysynth/samples/<lib>/...` (same layout as local `assets/samples/<lib>`), uploaded once
  by `scripts/upload_samples.ps1` (rsync/scp over the deploy key). Size ≈ 3.5 GB of 23 GB free.
- Manifest (built server-side from `assets/samples.json` + a file index generated by `scripts/build_sample_index.py`
  and uploaded with the samples; `samples/index.json`): per library {id, name, licence, group/category,
  totalBytes, entries: [{ sfz, name, files: [{path, bytes, sha256}] , bytes }]}. One SFZ entry = one playable
  instrument = the "single sample" download unit.
- Engine `SampleCache`:
  - Root `%LOCALAPPDATA%\keysynth\samples\<lib>\...`; sampler path resolution adds this root (first: repo/dev
    `assets/`, `KS_ASSETS_DIR`, then cache).
  - Units: **entry** (files of one SFZ incl. `#include`d/default_path files), **library**, **all**.
  - Download worker thread: queue, 2–4 parallel files, HTTP Range resume to `*.part`, SHA-256 verify, atomic rename.
  - Index `cache.json`: per file size/sha/lastUsed; per entry pinned flag. LRU eviction when over limit (setting,
    default unlimited — owner's PC), never evicts pinned or in-use.
  - Auto-fetch: loading a patch whose sampler SFZ is missing → enqueue that entry with priority; sampler shows
    `loading` until done (existing ReadOnly param) and reloads when complete.
  - Protocol: `samples_list` → per-entry status {cached, bytes, partial}, `samples_fetch {scope: entry|library|all,
    id}`, `samples_cancel`, `samples_delete {scope,id}`, `samples_pin`, events `samples_progress` (≤ 5 Hz),
    `samples_done`, `samples_error` (notify).
- Licences: platform is invite-only; files are served only to authorised users (no public URLs). Attribution in
  the UI library page (from manifest licence fields) and THIRD_PARTY_NOTICES.md.

## 6. Presets & plugins sync

- Local user data moves from `<repo>/userdata` to `%LOCALAPPDATA%\keysynth\userdata` for the installed app (dev
  checkout keeps `<repo>/userdata`; chosen by AppPaths: installed = exe not inside a git checkout).
- Engine `SyncService` (control/loader thread): on link + every 60 s + on local change: pull list (etags), download
  new/changed, push local changes. Conflict: last-writer-wins by `updatedAt`; loser kept as
  `<slug>.conflict-<ts>.json` locally. Deletions are tombstones server-side.
- Plugins: same for `userdata/plugins/<name>/` → hot reload picks them up (PluginHost watches that dir too).
- Factory presets and patterns ship with the installer (not synced).

## 7. Desktop app (Windows)

- `keysynth-engine.exe` gains a **tray icon** (JUCE `SystemTrayIconComponent`): tooltip = status (audio device,
  latency, cloud linked), menu: Открыть keysynth (opens `https://mvv42.ru/keysynth/`; if offline → local UI),
  Открыть локально, Перезапустить звук, Настройки звука…, Автозапуск ✓, Выход.
- Single instance (named mutex); second launch → focus/open UI. URL protocol `keysynth://open` registered by the
  installer → the web page's «Запустить» button can start the engine.
- Installer: **Inno Setup**, per-user install (`%LOCALAPPDATA%\Programs\keysynth`, no admin), Start menu shortcut,
  optional desktop shortcut, optional autostart (HKCU Run), protocol registration, uninstaller (keeps user data
  unless asked). Bundles: engine exe, `faust.dll` + Faust `share/faust/*.lib` (JIT), factory presets/patterns,
  `ui/dist` (offline fallback), licences. Icon: new `assets/icon/keysynth.ico`.
- Versioning: `vX.Y.Z` tags → `.github/workflows/release-windows.yml` (windows-latest): fetch Faust, configure
  (sfizz ON), build Release, run `ks-tests` (fast tier), build UI, Inno Setup → upload `keysynth-setup.exe` (stable
  name) + `keysynth-setup-X.Y.Z.exe` to the GitHub Release. Engine reports its version in `hello`; UI shows an
  update banner from `/api/releases/latest`.
- Unsigned binaries: SmartScreen «Подробнее → Выполнить в любом случае» — described in the install hint.

## 8. Web UI changes (ui/)

- Vite `base: '/keysynth/'` for the platform build (`npm run build:platform`); local build keeps `/`.
- `@mvv42/kit/platform` for `useMe`, `apiJson`, shell bridge (READY/THEME/AUTH); keep keysynth's own visual style
  (dark synth UI), use kit only where it doesn't clash (account button, login-required states).
- Engine discovery: try `ws://127.0.0.1:7341` with backoff; states: connecting / not installed (download card,
  launch button via `keysynth://open`, install hint) / connected. Remember «engine seen before» in localStorage.
- Account/link card, sync status, sample library page (tree: group → library → entries; sizes, cached status,
  progress, fetch entry/library/all, delete, pin, cache usage), update banner.

## 11. Review #1 decisions (override sections above where they conflict)

Security
- **Plugins are NOT synced in v1** (remote code execution risk). §6 covers presets only. Plugin sync later, with
  local confirmation + hash pinning.
- `baseUrl` is compiled in (`https://mvv42.ru/keysynth/api`, overridable only by CLI flag/env for dev); `cloud_link`
  carries only the token.
- WS sessions are tagged by Origin. `https://mvv42.ru` sessions: no plugin compile/reload, no arbitrary file paths
  (only preset slugs / sample ids), no `open_audio_panel`-style modal? (allowed — harmless). `Origin: null` rejected.
  Installed builds drop `:5173` dev origins. Both local ports require `Host` = `127.0.0.1:<port>` or
  `localhost:<port>` (DNS-rebinding guard). HTTP server binds 127.0.0.1 only.
- Manifest paths are validated before any write: reject `..`, absolute, drive letters, `:`, reserved device names,
  control chars; canonicalise; result must stay under the cache root. Server serves only paths present in its index.
- Device tokens: 180-day expiry, silently re-minted by the page when < 30 days left. The device scheme also rejects
  a token if the user's `last_app_ok_at` (updated on every cookie request passing `mvv42:app`) is older than 30 days
  → grant revocation / blocks take effect. `/api/devices` POST/DELETE are cookie-only. Bearer endpoints are not
  CSRF-exposed (no cookies). Auth: `AddMvv42Auth(...)` + `.AddScheme<..., DeviceTokenHandler>("device")`, policy
  `AnyUser` = (mvv42 cookie + app policy) OR (device).
- Re-linking to a different account requires explicit confirmation in the UI; userdata is per account
  (`userdata/accounts/<accountId>/presets`), first link merges and shows a summary.

Browser
- Auto-probe of `ws://127.0.0.1:7341` only if `engineSeen` (localStorage) or `permissions.query` says granted;
  otherwise a «Подключить движок» button (so no LNA prompt before install). Distinguish «permission denied» state with
  unblock instructions; Brave hint. Always `127.0.0.1`, never `localhost`.
- Shell iframe: verify in current Chrome whether same-origin iframe inherits local-network permission; add a
  registry `allow` field only if needed (token name verified in Chrome). Drop `midi; autoplay`.
- `keysynth://open` launch button: keep only if it works from the sandboxed iframe (test); otherwise hint to use
  Start menu.

Windows packaging
- Ship VC++ runtime DLLs app-local (faust.dll uses dynamic CRT). Inno `AppMutex=keysynth-engine` + close running
  engine before update. Autostart `HKCU\...\Run` → `keysynth-engine.exe --tray` (no browser). Second instance just
  opens the UI URL and exits. Installed mode detected by `installed.flag` next to the exe. AppPaths covers userdata,
  settings, logs, recordings, Faust cache, sample cache. Install hint mentions SmartScreen + Chrome "not commonly
  downloaded".

Samples
- Cut: LRU eviction, pinning, `samples_pin`. Delete is explicit only (refcounted shared files). 2 parallel downloads.
- Index builder uses the real SFZ parsing rules (`#include`, `#define`, `default_path`), stores case-corrected `/`
  paths matching the server filesystem. Resume with `Range` + `If-Range` (etag). `X-Accel-Redirect` percent-encoded;
  tests with spaces/Cyrillic/`#`. Deleting/replacing files in use: unload the sampler module first (or defer). Disk
  full → error event. nginx `limit_rate`/`limit_conn` on `_files` (VPN shares bandwidth). Cache root added to
  sampler path resolution and WS path allow-list.

Sync
- Engine is the only writer; presets endpoints are device-auth only (UI edits presets through the engine as today).
  Server revision number + `If-Match`; 412 → keep local as `<slug>.conflict-<ts>.json`. Tombstone vs offline edit:
  edit wins. Initial link: upload local user presets missing on server, download server ones missing locally.

CI / infra
- `max31000/keysynth` is public (release links) → it **cannot call private mvv42-infra reusable workflows**: inline
  copies of `deploy-static.yml` / `deploy-dotnet-api.yml` logic in `.github/workflows/` (note source + date for
  re-sync). Path filters: `server/**` → backend, `ui/**` → frontend, tags `v*` → release-windows. Container listens
  8080, host 127.0.0.1:5020, `volume-owner 1654:1654`.
- Cut `/api/releases/latest`; UI/engine query GitHub API directly.
- Order: WP0 contract (PROTOCOL.md cloud section + `docs/specs/...-api.md` REST contract) → A, B in parallel
  (B owns new files + protocol handlers; C owns main.cpp/tray/startup/CMake app target/installer) → C after B
  merges AppPaths → D → E. Infra part 1 (nginx conf, DB, apps row, secrets) before A's first deploy.
- Owner-only/manual steps listed in the final report: none expected except confirming prompts; the lead runs
  sync-secrets, `gh secret set`, nginx apply, server mkdir/DB, sample upload via the deploy key.
