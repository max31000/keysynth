# Remote control via backend relay (iPad as controller) — spec rev 1

Context: `docs/specs/2026-10-12-cloud.md` (+ §11), `docs/specs/2026-10-12-cloud-api.md`, `docs/PROTOCOL.md`,
`docs/research/MVV42_PLATFORM.md`. This spec only adds what is new.

## 1. Goal
Owner sits at the piano with an iPad: opens `https://mvv42.ru/keysynth/` (logged in), sees his PC engine, switches
presets / tweaks / runs drums. PC UI and iPad stay in sync. Works from any network. Account-scoped only;
signed-out users keep the local-only experience, no remote features visible.

Future (design must allow, not built now): Song library (sections → presets, tempo/style → drums, MusicXML notation
on iPad with a cursor following the transport, backing tracks played by the engine).

## 2. Topology
```
 controller (browser, platform cookie) ──wss /keysynth/api/relay──┐
                                                                  ▼
                                  keysynth-api RelayHub (in-memory, per user id)
                                                                  ▲
 host (keysynth-engine, device token)  ──wss /keysynth/api/relay──┘   outbound from the PC, no open ports
```
- **Host** = an engine instance (source of truth: PatchModel, transport). **Controller** = any browser tab (iPad,
  PC tab). Controllers hold no state; they render engine snapshots, exactly like today's local UI.
- The PC browser tab keeps using the direct local WS (lowest latency); it does NOT go through the relay. Both
  paths reach the same engine, which already broadcasts state changes to all its sessions.

## 3. Relay protocol (server)
Endpoint `GET /api/relay` (public `wss://mvv42.ru/keysynth/api/relay`), WebSocket upgrade.
- Auth at handshake: controller → platform cookie (`mvv42` scheme + app policy, Origin must be
  `https://mvv42.ru`); host → `Authorization: Bearer <device token>` (`device` scheme, same rules incl.
  `last_app_ok_at`). Query `?role=host|controller`. Role must match the scheme. Anything else → 401/403 before upgrade.
- Room = local user id. Messages never cross users.
- Frames are JSON text. Envelope:
  - host → server: `{ "t":"hello", "host": { deviceId, name, version, audio:{running,type,name,sampleRate,bufferSize,outputLatencyMs}, midiInputs:[...], lastNoteAt } }`,
    `{ "t":"status", ...same partial }` (on change, ≤ 1 Hz), `{ "t":"msg", "to":"<controllerConnId>|*", "msg":{…engine protocol message…} }`.
  - controller → server: `{ "t":"msg", "host":"<deviceId>", "msg":{…engine protocol request…} }`.
  - server → controller: `{ "t":"hosts", "hosts":[{deviceId,name,online,audio,midiInputs,lastNoteAt,version}] }` on
    connect and on any change; `{ "t":"msg", "host":"<deviceId>", "msg":{…} }`; `{ "t":"error", code }`.
  - server → host: `{ "t":"msg", "from":"<controllerConnId>", "msg":{…} }`, `{ "t":"controllers", "count": n }`
    (host may skip telemetry when 0).
- Server adds nothing to `msg`; it only validates size and the envelope. The engine is the authority for what a
  remote message may do (§5).
- Limits: frame ≤ 256 KB (patch snapshots), controller → host ≤ 60 msg/s burst 120, host → controllers ≤ 40 msg/s
  per controller (telemetry is throttled by the host, §5). Max 4 hosts and 8 controllers per user. Ping every 20 s,
  drop after 60 s silence. A second host connection with the same deviceId replaces the first.
- Implementation: ASP.NET Core WebSockets (`app.UseWebSockets`), `RelayHub` singleton (ConcurrentDictionary user →
  room), one bounded outgoing `Channel` per connection (drop oldest telemetry when full, never block the hub).
  Single API container → in-memory is fine; note for later scale-out (not needed).
- Revocation: on each host status/heartbeat, re-check device token validity every 5 min; controller cookies expire
  (10-min JWT) → server closes controller sockets whose token `exp` passed (client reconnects with refreshed cookie).

## 4. nginx (mvv42-infra)
New `location = /keysynth/api/relay` with its own WS proxy headers (`proxy_http_version 1.1`, `Upgrade`,
`Connection "upgrade"`, `proxy_read_timeout 75s`, `proxy_buffering off`), not the shared proxy snippet (which forces
`Connection ""`). Rate limit `limit_conn` 16 per IP on that location.

## 5. Engine (host)
- `cloud/RelayClient`: outbound WSS with WinHTTP WebSocket API (`platform/WinHttpWebSocket`, no new deps; ixwebsocket
  is built without TLS). Runs when linked; reconnect with backoff (1 s → 30 s, jitter); stops on unlink/401.
  Sends `hello` + `status` (audio/MIDI changes, `lastNoteAt` coarse to 1 s).
- Each relayed controller (`from` id) is a virtual `Session` with trust **remote**: allowed = state/catalog/list
  messages, `load_preset`, `set_param`, `set_zone`, `set_instrument`, `add/remove/move_fx`, `set_fx_bypass`,
  `note`/`cc` (virtual keyboard), `transport` + pattern messages, `panic`, `restart_audio`, `samples_list`/
  `samples_fetch`/`samples_cancel`, `sync_now`, `save_preset` (user presets only). Forbidden: plugins, audio device
  selection / `open_audio_panel`, `cloud_link`/`cloud_unlink`, any path outside logical ids, `set_patch` with
  arbitrary state paths (validated like web trust). Unknown → `error forbidden`.
- Telemetry to remote sessions: meters/CPU ≤ 10 Hz, MIDI note activity batched ≤ 15 Hz; skipped when the server
  reports 0 controllers.
- Responses and broadcasts go back as `{t:"msg", to:<conn>|"*"}`; broadcasts to all remote sessions use `*`.
- New engine protocol event for the future song features is NOT added now; transport position already exists.

## 6. UI (controller)
- Platform mode + logged in → open relay socket (cookie); `hosts` list. Target selection: if this browser is on the
  PC with a direct local engine → use local (no relay). Else pick automatically: online, audio running, MIDI input
  present, latest `lastNoteAt`; ties → last chosen (localStorage). Visible host switcher when > 1 online.
- The existing store/client gets a transport abstraction: `DirectTransport` (ws://127.0.0.1) and `RelayTransport`
  (envelope wrap/unwrap) with the same request/response/event API → all panels work unchanged.
- Touch layout (iPad, ≥ 768 px, coarse pointer): "Пульт" view — large preset tiles (favourites, recent, search),
  current preset name, master volume, drums start/stop + tempo, panic; full editor still reachable. Connection
  indicator with round-trip time.
- Signed out / no access: relay never opened; remote UI hidden; the gate shows only local options.
- Texts minimal (owner rule).

## 7. Security summary
Cookie-only for controllers, device-only for hosts, same-user rooms, engine-side remote trust tier, size/rate limits,
Origin check, token/grant revalidation, no new local listening ports.

## 8. Tests
Server: auth matrix (cookie vs bearer vs none per role), cross-user isolation, limits, replacement of duplicate host,
heartbeat timeout, revocation close. Engine: remote trust allow/deny table, envelope routing, reconnect/backoff with
a fake transport, telemetry throttling. UI: transport abstraction parity, host selection rules, relay reconnect.
E2E: local relay (server in dev + engine + mock browser client) — script `scripts/dev_relay_e2e.py`.

## 10. Review #1 decisions (override sections above)

1. **Origin**: RelayEndpoint rejects (403, before `AcceptWebSocketAsync`) a controller whose `Origin` is missing or not
   in `Mvv42AuthOptions.AllowedOrigins` (the SDK filter only covers unsafe methods; WS upgrade is GET). Hosts send no
   cookie; cookie + bearer together → 400.
2. **Long-lived controller sockets**: max 60 min; at ~50 min the client calls `getMe()` (refresh) and opens a new
   socket with the same `cid` (client-generated UUID, query `?cid=`), then closes the old one (make-before-break);
   server treats a known `cid` as resume. Grant checked at handshake only. Hosts: device token revalidated every 5 min.
3. **Remote trust** = `webRestriction(msg)` (Trust.cpp) + deny `cloud_link`, `cloud_unlink`, `set_audio_device`,
   `open_audio_panel`, `samples_delete`, `reload_plugin`; default-deny for unknown/new messages; `hello` reply carries
   `trust:"remote"`; UI hides denied features. Deny list test generated from the PROTOCOL message table.
4. **Envelope**: host→server `{t:"msg", to:"<cid>"|"*", except?:"<cid>", lossy?:true, msg}`; server→host
   `{t:"controller", cid, joined:bool}`, `{t:"msg", from:"<cid>", msg}`. Engine adds virtual clients `r:<cid>` to
   `ControlServer::clients_` (not new Sessions); `Target::Others` maps to `except`.
5. **Backpressure**: only `lossy` frames (telemetry, midi, samples_progress) may be dropped; non-lossy overflow →
   server closes that controller socket (4008); controller reconnects + re-`hello`s.
6. **Heartbeat**: app-level `{t:"ping"}`/`{t:"pong"}` every 20 s both ways; close after 45 s silence (net8 has no
   KeepAliveTimeout).
7. **Resync**: controller sends `hello` on every relay (re)connect and on host offline→online; on transport change
   all pending requests reject with `disconnected`; the id-less reply fallback in client.ts is disabled for relay.
8. **Rates**: host coalesces `param` per (node,param) ≤ 20 Hz for remote clients; RelayTransport coalesces
   `set_param` ≤ 30 Hz; server safety caps close the socket: controller 100 msg/s, host 300 msg/s.
9. **Frame caps**: host→server 1 MB, controller→server 128 KB (measure catalog_ok / samples_list_ok in tests).
10. **WinHTTP**: `WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`; min OS Windows 8.1; bearer via `WinHttpAddRequestHeaders`;
    401/403 at upgrade → same CloudServices 401 path (drop token, `cloud_status`).
11. **nginx**: `location = /keysynth/api/relay` sets Host/X-Forwarded-For/X-Forwarded-Proto/Upgrade/Connection
    itself, `proxy_read_timeout 90s`, `proxy_buffering off`. `limit_conn_zone` needs the http context → infra-level
    change in the shared http conf (if not feasible, skip limit_conn; server caps suffice).
12. PC tab with a direct engine never opens the relay.
13. iPad Safari: on `visibilitychange`→visible skip backoff, reconnect + re-`hello`; `navigator.wakeLock` while the
    «Пульт» view is open; hidden tab sends `{t:"pause"}`/`{t:"resume"}` → host skips telemetry for that cid.
14. **Cut**: `lastNoteAt`, `midiInputs`, host `status` stream. Host `hello {deviceId,name,version}`; hosts list =
    online/offline. Selection: one online → it; else last chosen; else switcher.
15. **Cut** the transport abstraction: RelayTransport is a `WebSocketLike` adapter for `client.ts` (wrap/unwrap).
16. Future songs: `song_*` message family + a separate lossy `position` event (≥ 30 Hz) for the score cursor; no
    envelope change needed.
17. Extra tests: Origin missing/foreign → 403, `cid` resume, overflow close on non-lossy, remote deny table.
